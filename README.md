# AI Energy — Unified Energy Management System

This project provides tools for monitoring, checking, and reporting on smart meter data from an Industrial Energy Management System. It connects to a MySQL database that stores high-frequency telemetry from electrical meters.

---

## Project Structure

### `check/` — Data Quality & Diagnostic Scripts

Scripts for validating and inspecting meter data quality, gaps, and reporting patterns.

| File | Purpose |
|------|---------|
| **`data-source.py`** | Analyzes the **utility source meter** (energy/billing data) for a given date. Queries the `site_energy_YYMMDD` table (the "odometer" table with cumulative kWh), computes daily consumption from TotalEP/ImpEP/ExpEP, and generates an HTML report (`Source-Energy-ID{n}.html`) with KPIs and raw billing data. |
| **`data-meter-49.py`** | Performs a **single-meter deep dive** for Meter ID 49 (configurable). Reads power quality data from `site_power_YYMMDD` for one day, computes time intervals between records, plots a bar chart of packet intervals, and generates an HTML report with voltage/current/power stats plus a raw data log. Highlights gaps (e.g., intervals &gt;20 min) in orange/red. |
| **`data-gaps.py`** | **Gap analysis** across all meters for a given date. Compares each meter's timestamps against an expected frequency (e.g., 5 min). Identifies meters with missing data points (gaps), dead meters (no data), and perfect meters. Outputs a CSV report (`gap_report_YYMMDD.csv`). |
| **`data-frequency.py`** | **Diagnostic tool** to determine the actual reporting rhythm of meters. Finds an active meter, computes time deltas between records, and reports the mode (most common interval), min/max/mean. Suggests `EXPECTED_FREQ` (e.g., `5min`, `15min`, `60min`) for use in other scripts. |

---

### `db/` — Database Schema & Connectivity

Utilities for connecting to the MySQL database, inspecting permissions, and managing the schema.

| File | Purpose |
|------|---------|
| **`connect.py`** | **Simple connection test** to the unified MySQL database. Establishes a connection, runs a sample query (`meter_info`), and prints the first 5 meters. Use this to verify connectivity and credentials. |
| **`permissions.py`** | Shows the **current user** and **raw GRANTS** for the connected MySQL account. Useful for debugging permission issues. |
| **`schema.py`** | **Schema dump script**. Connects to the database, iterates over all tables and views, runs `SHOW CREATE TABLE` for each, and writes a full SQL dump to `full_schema_python.sql` (DROP + CREATE statements). |
| **`schema.sql`** | **Full database schema export** — a large SQL file containing DROP/CREATE statements for all tables (e.g., `meter_info`, `meter_type`, `site_power_*`, `site_energy_*`, pricing, power factor, etc.). Typically generated by `schema.py`. |
| **`definitions.md`** | **Schema documentation** for the unified EMS database. Describes core tables (`meter_info`, `meter_type`, `electricity_pricing`), telemetry tables (`site_power_*`, `site_energy_*`), financial logic, and user/session management. Explains columns, units, and sample queries. |

---

### `report/` — HTML Report Generators

Scripts that produce human-readable HTML reports for monitoring meter health and data quality.

| File | Purpose |
|------|---------|
| **`data-frequency-report.py`** | **Daily meter frequency report**. For a given date (YYMMDD), analyzes all meters against an expected interval (e.g., 15 min → 96 records/day). Computes uptime %, record count, avg interval, and first/last seen time. Generates an HTML report (`Frequency-20YYMMDD.html`) with a summary (dead/low/perfect counts) and a sortable table sorted by uptime. |
| **`data-frequency-report-weekly.py`** | **Weekly meter health report**. Aggregates data over 7 days (configurable start date). Queries each daily `site_power_*` table, counts records per meter per day, and produces an HTML report (`Weekly-Report-YYYY-MM-DD.html`) with a heatmap (Mon→Sun) for each meter, weekly uptime %, and total records vs. target. |

## Configuration

Most scripts share a common database configuration:

- **Host:** `localhost`
- **Port:** `3307`
- **Database:** `unified`
- **User:** `energy_user`

Target dates, meter IDs, and expected frequencies are set at the top of each script (e.g., `TARGET_DATE`, `TARGET_METER_ID`, `EXPECTED_FREQ_MIN`).

---

## Dependencies

- Python 3
- `mysql-connector-python`
- `pandas`
- `matplotlib` (used by `data-meter-49.py`)

---

## Quick Start

1. **Verify DB connection:**  
   `python db/connect.py`

2. **Check reporting frequency:**  
   `python check/data-frequency.py`

3. **Generate daily report:**  
   `python report/data-frequency-report.py`

4. **Generate weekly report:**  
   `python report/data-frequency-report-weekly.py`
